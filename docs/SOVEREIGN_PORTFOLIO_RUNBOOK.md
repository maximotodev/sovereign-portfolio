# Sovereign portfolio: release and trust boundaries

## Public site
The portfolio's active public routes are /, /systems, /newsletter,
and /newsletter/essay/<slug>. Older /blog/<slug> links remain valid and
canonicalize to the Newstr archive.

The read-only Nostr archive uses original signed kind-30023 events. Its
checked-in snapshot is `src/lib/newstr-verified-events.json`. This file
is initially empty until a maintainer explicitly refreshes it. An empty
snapshot must never be described as confirmed published content. At runtime,
the public client verifies every snapshot/relay event again and tries multiple
relays. Disconnected relays must not remove already-verified cached posts.

## Refresh a signed snapshot
Run `npm ci`, then:

```bash
node scripts/refresh-newstr.mjs --dry-run
node scripts/refresh-newstr.mjs
git diff -- src/lib/newstr-verified-events.json
```

Review every fetched event's identity, title, links, and content before
committing. The command never signs, broadcasts, or deploys anything.
Commit only public authored events. Keep the snapshot under version control
and do not inject unsigned placeholder content.

## Security boundaries
The old public chat and database guestbook API routes were not used by the
redesigned public pages. They were removed instead of retained as a dormant,
unrate-limited attack surface. No service-role token or model credential is
needed for core reader routes. The Studio remains a separate human-driven
NIP-07 signing workflow on /studio; do not invoke that workflow from agent
code, static site gateways, or build automation.

Vercel sends defense-in-depth browser headers. CSP is report-only pending
real browser testing of dynamic Next scripts and external relay connections.
Only move to an enforced CSP after an observed violation review.

## SEO and performance
/robots.txt and /sitemap.xml are generated by Next metadata routes;
the old blog URLs have canonical metadata to the unified Newstr archive.
`NEXT_PUBLIC_SITE_URL` can override the canonical origin at build time,
but should remain the independent public origin for SEO. Verify social cards,
keyboard/touch navigation, Lighthouse mobile, and redirects during review.

## nsite experiment
The static mirror remains a **manual** experiment. On an untrusted gateway,
Studio should be read-only; API endpoints are not part of the static export.
Use the previously prepared isolated `scripts/nsite-export.mjs` workflow
until it is integrated into CI. No DNS or Nostr publishing changes are made
by this refactor.

## Release gates
- `npm ci && npm run build` and `npx tsc --noEmit`
- `node --experimental-strip-types --test tests/*.test.mjs`
- Vercel preview READY, /robots.txt and /sitemap.xml return 200
- Check Newstr filter controls and signed-only labels
- Test 320px viewport, keyboard focus, zoom, reduced motion
- Verify /api/chat and /api/guestbook return 404
- Review repo diff and obtain human merge approval
